OSI参照モデルとTCP/IP階層

基本情報・応用情報 頻出

ネットワーク通信を7つ(または4つ)の層に分けて考える、通信技術の共通言語。基本情報・応用情報のネットワーク分野で最頻出のテーマの1つ。

そもそも、なぜ層に分けるのか

通信の仕組み全体を1つのかたまりとして考えると複雑すぎるため、役割ごとに層(レイヤー)に分割し、 各層は1つ下の層が提供する機能だけを使い、1つ上の層に決まった形で機能を提供するという約束事にした。 これにより、ある層の実装(例: 物理的な回線の種類)が変わっても、他の層(例: アプリケーションの処理)は影響を受けずに済む。 Lesson1-1(アーキテクチャ)で見た「依存の向きを整理する」という発想が、ネットワークの世界にも同じ形で現れている。

7アプリケーション層 — HTTP・メール(SMTP)等、利用者向けの通信
6プレゼンテーション層 — データの形式・文字コード・暗号化の変換
5セション層 — 通信の開始から終了までの管理
4トランスポート層 — TCP・UDP、通信の信頼性を担保
3ネットワーク層 — IP、宛先までの経路選択(ルーティング)
2データリンク層 — MACアドレス、隣接機器間の通信
1物理層 — ケーブル・電気信号など物理的な伝送路

OSI参照モデルは7層(上から7〜1、試験では番号と役割の対応がよく問われる)。実際のインターネットで使われているTCP/IPは、これを4層(アプリケーション層/トランスポート層/インターネット層/ネットワークインターフェース層)に簡略化した実装モデル。

TCP(トランスポート層)

コネクションを確立し(3ウェイハンドシェイク)、パケットの到達確認・再送・順序保証を行う「信頼性重視」のプロトコル。Webページの表示やファイル転送など、データが1つも欠けてはいけない通信に使う。

UDP(トランスポート層)

コネクションを確立せず、到達確認や再送も行わない「速度・軽さ重視」のプロトコル。多少のデータ欠落より遅延の少なさが重要な、動画配信・音声通話・オンラインゲームなどに使う。

IP(ネットワーク層)

宛先のIPアドレスをもとに、どの経路を通ってデータを届けるか(ルーティング)を担う。Lesson2-1で見たHTTP通信は、このIP層の上に成り立っている。

具体例

Webサイトを開く時: ブラウザ(アプリケーション層、HTTP/HTTPS)が要求を作り、TCP(トランスポート層)がそれを確実に届く形に分割・管理し、 IP(ネットワーク層)が宛先サーバーまでの経路を決め、実際の配線・電波(物理層)を通ってデータが流れる、という具合に各層が積み重なっている。

要点
  • OSI参照モデルは7層、実際のインターネットで使うTCP/IPは4層に簡略化した実装
  • TCP=信頼性重視(再送・順序保証あり)、UDP=速度重視(再送・順序保証なし)
  • IP=宛先までの経路選択(ネットワーク層)
確認問題1(FE形式)

Q. 動画のライブ配信のように、多少のデータ欠落より低遅延を優先したい通信に適したプロトコルはどれか。

選択肢と答えを見る

ア: TCP / イ: UDP / ウ: HTTP / エ: IP

正解: イ(UDP)。再送制御を行わない分オーバーヘッドが少なく低遅延。TCPは信頼性を優先するため、再送待ちが遅延として現れやすい。

確認問題2(FE形式)

Q. OSI参照モデルで、IPアドレスに基づく経路選択(ルーティング)を担当する層はどれか。

選択肢と答えを見る

ア: データリンク層 / イ: ネットワーク層 / ウ: トランスポート層 / エ: セション層

正解: イ(ネットワーク層)。データリンク層はMACアドレスによる隣接機器間の通信、トランスポート層はTCP/UDPによる通信の信頼性を担当する。
