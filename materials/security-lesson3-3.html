⏱ 所要時間の目安: 約15分
06

代表的な攻撃手法と対策

基本情報・応用情報 頻出

「攻撃名」だけでなく「どういう仕組みで成立し、どう防ぐか」までセットで押さえる。基本情報・応用情報のセキュリティ分野で最頻出。

SQLインジェクション

入力フォームに、意図しないSQL文の断片を混入させ、データベースを不正に操作する攻撃。例: ログインフォームに' OR '1'='1のような文字列を入力し、認証を無理やり通す。対策: 入力値をそのままSQL文に組み込まず、プレースホルダ(バインド変数)を使う。

XSS(クロスサイトスクリプティング)

攻撃者が悪意あるスクリプトをWebページに埋め込み、それを見た他の利用者のブラウザ上で実行させる攻撃。Cookie(セッション情報)の盗み出し等に悪用される。対策: 利用者からの入力をそのままHTMLとして出力せず、エスケープ処理(<等の特殊文字を無害化)する。

CSRF(クロスサイトリクエストフォージェリ)

利用者が別のサイトにログインしたままの状態を悪用し、利用者が意図しないリクエスト(例: 送金・退会)を、悪意あるサイト経由で勝手に送信させる攻撃。対策: リクエストごとに正規の画面経由でしか発行されない使い捨てトークン(CSRFトークン)を要求する。

DoS/DDoS攻撃

大量のリクエストを送りつけ、サーバーやネットワークを過負荷にしてサービスを利用不能にする攻撃。1台から行うのがDoS、多数の端末(踏み台にされたもの含む)から一斉に行うのがDDoS。対策: WAF・CDNによるトラフィックの分散/フィルタリング、アクセス数の異常検知。

SQLインジェクションの具体的な流れ

SELECT * FROM users WHERE id = '入力値' という組み立て方をしているとき、入力値に ' OR '1'='1 を入れると、 実行される文が SELECT * FROM users WHERE id = '' OR '1'='1' となり、'1'='1'が常に真になるため全件が条件を満たし、 本来アクセスできないはずのデータまで取得・操作されてしまう。プレースホルダを使えば、入力値は「値」として扱われ、SQL文の構造そのものを書き換えられなくなる。

要点
  • SQLインジェクション=入力値でSQL文自体を書き換える → プレースホルダで対策
  • XSS=悪意あるスクリプトを他人のブラウザで実行させる → 出力時のエスケープで対策
  • CSRF=ログイン状態を悪用し意図しないリクエストを送らせる → CSRFトークンで対策
  • DoS/DDoS=大量アクセスでサービスを止める → WAF・CDN・異常検知で対策
確認問題1(FE形式)

Q. Webアプリの入力フォームから悪意あるSQL文の断片を混入させ、データベースを不正操作する攻撃への対策として最も適切なものはどれか。

選択肢と答えを見る

ア: 入力値をエスケープしてHTMLとして出力する / イ: プレースホルダ(バインド変数)を使ってSQL文を組み立てる / ウ: CSRFトークンを発行する / エ: アクセス数を監視する

正解: イ。アはXSS対策、ウはCSRF対策、エはDoS/DDoS対策にあたる。

確認問題2(FE形式)

Q. 利用者が別サイトにログイン中であることを悪用し、利用者の意図しない送金リクエストを勝手に送信させる攻撃はどれか。

選択肢と答えを見る

ア: SQLインジェクション / イ: XSS / ウ: CSRF / エ: DDoS攻撃

正解: ウ。ログイン状態(セッション)を悪用して、利用者本人になりすましたリクエストを送らせるのがCSRFの特徴。
