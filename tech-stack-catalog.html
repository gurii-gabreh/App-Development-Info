01

GitHub Pages + GitHub Actions

静的ホスティング + 自動化(CI/CD)

最適な用途

サーバー側処理が不要な静的サイト(HTML/CSS/JS、JSONを直接fetchして表示するダッシュボード等)。mainへのpushをトリガーに自動デプロイできるため、このセッション(Claude Code)だけでcommit→push→公開まで完全に完結できるのが最大の利点。

使用できる条件(無料枠等)

公開サイトのサイズ1GBまで(ソースリポジトリも1GB推奨上限)、帯域は月100GBのソフトリミット、ビルドは1時間10回のソフトリミット(ただしカスタムのGitHub Actionsワークフローでビルド・公開する場合はこの制限の対象外)、デプロイは10分でタイムアウト。GitHub Actionsは2026年1月の改定でFreeプラン月2,000分(パブリックリポジトリの標準ランナーは無制限無料とする記事もあり)。

どのアプリで使ったか

  • progress-tracker-dashboard: dashboard.html本体、deploy-pages.yml
  • App-Development-Info: 学習資料・学習方針・図の種類・UI要素名称集
  • servicenow-sub-agent: AI研究ビューアーサイト
  • claude-voice-bridge: 拡張機能に関連する公開ページ
  • Task-WBS: WBSカレンダー表示

⚠ 懸念箇所

サーバー側処理(APIキーを隠した外部連携・Webhook受信・認証・定期cron)ができない。データはJSONファイルをgit管理する形になるため、大規模なリレーショナル検索には不向き。

必要な設定

リポジトリのPages設定を有効化するだけ(初回のみユーザー側でON)。以降の更新はClaude Code側のgit push+Actionsで完結し、追加のユーザー操作は不要。

公式ドキュメント: https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits

確認日: 2026-11-02 ／ 情報の確度: official(GitHub Pagesの制限値のみ公式ドキュメントで確認。Actionsの無料枠分数は二次情報)

02

Google Apps Script(GAS) + Google Sheets

軽量バックエンド + スプレッドシートDB

最適な用途

スプレッドシートを人が直接見る/編集するUIとして使いたい場合。Webアプリとしてデプロイすれば、認証無しの簡易API(doGet/doPost)としても使える。

使用できる条件(無料枠等)

スクリプト本体の実行時間は1実行あたり6分、カスタム関数は30秒、同時実行数は30、という情報があるが2026年時点の正確な数値は公式未確認。

どのアプリで使ったか

  • progress-tracker-dashboard: gas/Code.gs、GASウェブアプリ経由の依頼タスクタブ⇄完了タブ移動(README記載、現在はtasks.json直接管理が主流で縮小傾向)
  • ai-research-radar: Gemini APIによる1日1回自動調査、依頼タスクタブのステータス直接更新
  • study-app: gas/
  • gemini-monitor: gas/
  • claude-voice-bridge: gas/
  • supermarket-price-tracker: Code.gs
  • prompt-manager: Code.gs

⚠ 懸念箇所

コード変更のたびに手動での再デプロイが必要(GitHubと自動連携していない)。ghGetJson_/ghPut_パターンはファイル全体を読んで全体を書き戻す方式のため、頻繁に書くログと滅多に書かないデータを同居させると非効率(data/claude-core-rules.mdルール29参照)。

必要な設定

初回のGASエディタでのデプロイ(ウェブアプリとして公開、アクセス権限設定)はユーザー側で行う必要がある。コード自体はClaude Codeが書ける。

確認日: 2026-11-02 ／ 情報の確度: secondary(実行時間等のクォータ数値は二次情報のみ、公式クォータページ未確認)

03

Cloudflare Workers + D1 + Pages + Workers AI

サーバーレスバックエンド + SQLiteデータベース + AI推論

最適な用途

本格的なサーバー側処理(認証・暗号化・定期cron・AI推論)が必要なアプリ。D1はSQLite互換のリレーショナルDBとして使える。

使用できる条件(無料枠等)

Workers無料枠は1日10万リクエスト(UTC 0時リセット)、CPU時間30ms、スクリプトサイズ1MB。Pagesは月500ビルド・同時1ビルド・ファイル数2万。D1の無料枠の具体的数値は今回未確認。

どのアプリで使ったか

  • kizashi: 都知事杯オープンデータ・ハッカソン2026提出作品。D1(事案データ)・Workers AI(傾聴AIチャット)・cron(毎日19:00 UTC=日本時間4:00に事案自動削除)を使用。本番URL: kizashi-app.yui-gurii.workers.dev

⚠ 懸念箇所

実際のCloudflareアカウントへのデプロイ(wrangler login/d1 create/secret put/deploy)はユーザー自身の認証情報が必要で、このセッションだけでは完結できない(PTD系の他アプリと違う最大の制約)。ハッカソン等でイベント運営から「Paidプラン相当」の招待を受けた組織アカウントを使う場合、自分がBilling権限を持たない可能性があり、請求状況の自己確認ができないことがある(2026-11-01、kizashiのtokyo_odh_260アカウントで確認)。

必要な設定

wrangler login(ブラウザでの認証)、D1データベースの実体作成、マイグレーション適用、secret put(APIキー等。Claude Codeは入力しない)、wrangler deploy。いずれもユーザー自身の操作が必要。

確認日: 2026-11-02 ／ 情報の確度: secondary(Workers/Pagesの無料枠数値は二次情報、公式Limitsページ未確認。D1は未確認)

04

ServiceNow PDI(Personal Developer Instance)

無料開発者インスタンス(Scheduled Job・REST連携)

最適な用途

定期実行(Scheduled Job)でAPI/RSSから情報を自動収集し、GitHub Actionsへエクスポートするパイプライン。

使用できる条件(無料枠等)

個人開発者向けに無料で提供されるインスタンス。定期的に使わないと非アクティブ判定され、最終的に回収(reclaim)される可能性がある(具体的な日数は公式未確認)。回収されると復旧できない。新規申請の待機期間は2〜3週間以上かかる場合があるとの報告あり。

どのアプリで使ったか

  • servicenow-sub-agent: AI/開発関連情報の自動収集パイプライン(Scheduled Job→REST Message→u_ai_research_itemテーブル→GitHub Actionsでresearch-items.jsonへエクスポート)

⚠ 懸念箇所

非アクティブによる自動回収リスクがある(定期的なログイン・利用が必要)。障害時にPDI自体が一時利用不可になることがある(2026年7月に発生例あり、コミュニティ報告ベース)。

必要な設定

developer.servicenow.comでのPDI申請・取得(ユーザー側)。Scheduled Job・REST Messageの設定はClaude Codeが支援できるが、PDIへのログイン自体はユーザーの認証情報が必要。

確認日: 2026-11-02 ／ 情報の確度: secondary(ServiceNow公式ドキュメントではなくコミュニティ投稿ベース)

05

LINE Messaging API

メッセージング連携(無料コミュニケーションプラン)

最適な用途

ユーザーへのプッシュ通知・Bot的な応答機能。

使用できる条件(無料枠等)

無料の「コミュニケーションプラン」は月200通まで(送信回数×友だち数で計算)。応答メッセージ(Reply API)は無料枠にカウントされない、とする解説が複数あるが公式料金ページでの裏付けは今回未確認。2026年10月に追加メッセージの単価改定があったとの報道あり(具体的な金額は未確認)。

どのアプリで使ったか

  • kizashi: crisisResponse.js・chat.jsで使用

⚠ 懸念箇所

無料枠の月200通は少なく、友だち数が増えると配信回数が制限される。応答メッセージ中心の設計にすれば枠消費を抑えられる(二次情報ベース)。

必要な設定

LINE Developersコンソールでのチャネル作成・アクセストークン発行はユーザー側で行う必要がある。

公式ドキュメント: https://developers.line.biz/ja/docs/messaging-api/overview/

確認日: 2026-11-02 ／ 情報の確度: secondary(無料枠の通数等は二次情報、公式料金ページでの金額未確認)
